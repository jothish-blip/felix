## Controlled Fixture Testing Strategy

All verification and assessment capabilities are rigorously validated against controlled local fixtures before deployment:
1. **Network Isolation:** No unit or integration test touches third-party servers, cloud providers, or public endpoints.
2. **Mock Servers:** Uses standard `net/http/httptest` servers to simulate exact HTTP response codes (200, 401, 403, 404, 500), headers, and payloads.
3. **Synthetic Provenance:** Fixture-backed test data is explicitly tagged with `PROVENANCE_FIXTURE` or `PROVENANCE_MOCK` to prevent confusion with live production discoveries.
4. **Deterministic Reproducibility:** All tests use fixed seeds, deterministic hashing, and stable sort ordering to ensure 100% reproducible outcomes across platforms.

## Authorized Real-Target Operational Bounds

When executing audits against authorized client targets under formal mandate:
- **Scope Enforcement:** Every request is validated against authorized hostname and path boundaries. Cross-domain redirects are blocked.
- **Rate & Concurrency Limits:** Crawling and probing respect worker pool limits (default 10 concurrent requests).
- **Non-Destructive Guarantee:** Probes are limited to read-only inspections (`GET`, `OPTIONS`, `HEAD`). Mutating operations (`POST`, `PUT`, `DELETE`) are strictly blocked unless explicit write authorization is configured.
- **Fail-Closed Verification:** Any network failure, timeout, or ambiguity defaults to `INCONCLUSIVE` or `NOT_VERIFIED`, never falsely claiming target vulnerability.

## Explicit Non-Goals & Deferred Capabilities

To maintain commercial reliability, safety, and single-binary portability, the following items are explicitly **deferred or non-goals**:
1. **Destructive Exploitation:** Felix does not attempt active database exploitation, remote code execution, or administrative account takeover.
2. **CGO / External Runtimes:** Felix will not adopt dependencies requiring CGO, Node.js drivers, Python runtimes, or external databases.
3. **Generic Compliance Checklists:** Felix reports empirical security exposures, not checkbox compliance audits (e.g. PCI-DSS, SOC 2 checklist questionnaires).
4. **Autonomous Remediation / Patching:** Felix reports facts and safe reproduction steps; automated patching of client source code is out of scope.
